# SOMEON(개발 때 이름 Drive Mate) 개발 로드맵

기획: [OVERVIEW.md](OVERVIEW.md) · SDK 사실관계: [PLEOS_SDK_NOTES.md](PLEOS_SDK_NOTES.md)(함께로 프로젝트에서 2026-10-30에 확인한 내용)

현대자동차그룹 차량용 앱 공모전 출품작(함께로 대신, 2026-11-02 결정). **제출 마감 2026-11-15 23:59**

## 개요의 우선순위 검토 (2026-11-02)

| 개요의 계획 | 확인한 내용 | 조정 |
|---|---|---|
| 1차: Vehicle SDK로 주행·정차 UI 제어 + 기본 매칭 | Vehicle SDK는 바로 사용 가능. 기어 읽기와 정차 판정은 함께로에서 검증한 코드를 재사용할 수 있음 | 상태별 UI는 그대로 1순위. 다만 이동 데이터 없는 "기본 매칭"은 일반 소개팅 앱과 같아서, 심사 포인트인 차량 특화성과 창의성이 드러나지 않음. 매칭은 처음부터 이동 패턴 점수로 만듦 |
| 2차: FusedLocation으로 생활권 매칭 | FusedLocation은 Playground에서 아직 "준비 중"(Coming Soon) | 위치 소스를 인터페이스로 분리함. 우선 안드로이드 기본 위치 API로 구현하고(에뮬레이터 경로 재생으로 시험), SDK가 열리면 교체 |
| 확장: NaviHelper로 만남 장소 추천 | NaviHelper는 지금 사용 가능(목적지 설정, 경유지) | "왜 차에서?"에 대한 가장 강한 답(매칭 → 만남 장소 → 바로 길안내)이라 핵심 범위로 당김. 다만 최소 버전만: 장소 목록에서 추천하고 목적지 설정 |
| TTS/STT 단계적 적용 | TTS·STT 모두 ON_DEVICE 모드는 등록 없이 사용 가능 | TTS는 주행 중 알림에 바로 사용. STT로 상대와 대화하는 기능은 운전 중 주의 분산 때문에 제외하고, 짧은 명령("나중에 알려줘")만 검토 |

## 추가 고려사항

- **시연과 콜드 스타트**: 매칭에는 상대가 있어야 함. 서버에 가상 사용자를 미리 넣어 두고, 두 번째 운전자(가상 차)의 출퇴근 시나리오로 언제든 같은 장면을 재현할 수 있게 함
- **출퇴근 패턴은 며칠치 기록이 있어야 나옴**: "일주일 출퇴근" 경로 시나리오 파일을 만들어 테스트와 시연에 같이 씀(함께로의 양재→경포대 시나리오 방식)
- **위치 = 스토킹 위험**: 원본 위치는 기기에만 둠. 서버에는 생활권(동 단위)과 시간대로 요약한 값만 보냄. 상대에게는 매칭 전에 동네 이름 수준만 보이고, 실시간 위치는 끝까지 공유하지 않음. 만남 장소는 공개된 장소만
- **법·심사**: 위치정보법(개인위치정보 수집 동의, 실서비스 시 위치기반서비스사업자 신고), 만 19세 이상과 본인인증(프로토타입은 모의), 신고·차단, 탈퇴 시 삭제. 도로교통법 제49조와 Pleos 심사 기준에 따라 주행 중 영상 표시와 조작은 금지
- **주 사용자는 혼자 출퇴근하는 운전자**: 탐색과 입력은 도착 후 P단에서만 함. 입력이 많은 프로필 작성은 휴대폰 웹페이지로 받는 방법도 검토(함께로의 동승자 페이지 방식)
- **탐색·스와이프 없음**: 하루에 몇 명만 추천하고 추천 이유를 보여 줌. 운전 중 탐색 문제를 원천적으로 없애면서 "검색 대신 생활 패턴"이라는 차별점도 됨

## 공통 원칙

- 정차 판정: 기어 P가 1.5초 유지돼야 정차(SDK가 구독 직후 P를 한 번 보내는 문제 때문, 함께로에서 확인)
- 주행 중 화면: 정적인 안내 한 장만(사진·프로필·목록 없음). 알림은 TTS 한 문장
- 권한 요청은 P단에서만(주행 중에는 시스템 허용 창이 막힘)
- 검증은 에뮬레이터 + Virtual Console(`tools/vconsole.py`) + 경로 시나리오로

### Step 1. 주행·정차 상태 게이트 ✅
- Vehicle SDK로 기어 구독, P가 1.5초 유지되면 정차(`drive/DriveSession.parked`). 정차 화면(`ParkedScreen`)과 주행 화면(`DrivingScreen`) 분리
- 주행 화면: "운전 중 / 새 소식은 음성으로 알려 드려요 / 확인은 정차(P) 후에" 정적 안내와 대기 중인 소식 개수만
- 소식(`notice/NoticeCenter`): 주행 중에는 TTS로 "…정차한 뒤 화면에서 확인하세요"만 말하고 쌓아 둠. 정차하면 "정차했어요. 새 소식 N개를 화면에서 확인하세요" 후 정차 화면에 카드로 표시, "확인"으로 지움
- 확인(에뮬레이터): P → D(60km/h) → 소식 도착(음성) → P(음성 + 카드) → 확인. 단위 테스트 `NoticeCenterTest`

### Step 2. 이동 기록 → 생활 패턴 ✅
- 위치: 안드로이드 위치 서비스 GPS(`location/LocationSource`, 5초 간격). FusedLocation SDK가 열리면 이 클래스만 교체
- 운행 기록(`core/TripTracker`): P를 떠날 때부터 다음 정차(P 1.5초)까지 한 번. 1분 미만이거나 300m 미만 이동(재주차)은 버림. 앱을 주행 중에 켜면 다음 운행부터 기록
- 기록은 이 차에만 저장(`trip/TripStore`, 앱 내부 파일). 내비가 앞에 있어도 계속 기록하도록 위치 포그라운드 서비스(`trip/RecordingService`)
- 생활 패턴(`core/PatternFinder`): 운행 끝점 600m 이내는 같은 장소. 같은 두 장소 사이를 45분 이내 출발 시각으로 서로 다른 날 3번 이상 다니면 "자주 다니는 길"(예: 평일 08:00~08:30 분당 정자동 → 판교 삼평동). 장소 이름은 내장된 동 목록(`core/Neighborhoods`)에서. 패턴에 담기는 위치는 약 1km 격자 중심뿐(`GeoPoint.coarse`)이라 집 위치가 드러나지 않음
- 동의 화면(정차 중): "동의하고 기록 시작" → 위치 권한 → 기록 시작. 새로 찾은 길은 소식으로 알림
- 시나리오: `tools/scenarios/commute_week_A.csv`(분당 정자동 ↔ 판교), `commute_week_B.csv`(수지 풍덕천동 ↔ 판교, A와 회사 동네·출근 시간이 겹침). `# expect:` 줄이 기대하는 자주 다니는 길이고 `PatternFinderTest`가 비교. 디버그 앱은 같은 파일로 일주일치를 넣을 수 있음
- 확인(에뮬레이터): 동의 → 권한 허용 → A 일주일 주입(길 2개 발견, 음성 1번) → 실제 운행 1회(판교 → 정자동, `adb emu geo fix`로 이동) 기록

### 디자인 정리 ✅ (Step 3 전)
- 사용자가 만든 시안(정차 화면)대로 구성: 왼쪽 메뉴(홈·오늘의 추천·매칭/대화·만남 장소·내 프로필·설정), 홈 상단 배너와 "내 드라이빙 프로필", "오늘의 추천 인연" 카드(사진·일치도·출퇴근·생활권·관심사·한 줄 소개·관심사 사진, 다음에/관심 있어요), "이동 패턴 매칭"(나와 상대 동네 벤다이어그램, 일치도, 연결 이유, 작은 지도), "함께 가기 좋은 만남 장소 보기"
- 배너·프로필·관심사·카페 사진은 시안 이미지에서 잘라 씀(`res/drawable-nodpi`)
- 내 드라이빙 프로필, 벤다이어그램과 지도의 "나"는 실제 생활 패턴. 추천 인연 3명은 Step 3 전까지 쓰는 예시(`demo/SampleRecommendations.kt`, 지연 = 시나리오 B). 사진이 없는 사람은 "서로 관심을 보이면 사진이 열려요"
- 주행 화면도 같은 톤으로(로고 + 정적 안내)

### 디자인 2차: Pleos 주간·야간 테마 ✅ (Step 5 전)
- 검토 결과: Pleos 시스템 화면은 주간에 흰색·밝은 회색, 야간 모드에서 검은색으로 바뀌는데(에뮬레이터에서 `cmd uimode night yes`로 확인) 앱은 항상 어두워서 주간에 혼자 떠 보였음. Pleos 디자인 가이드도 "주변 밝기에 따라 밝기·대비를 자동 조정", 대비 4.5:1 이상, 글자 높이 18px 이상, 텍스트 최소화를 요구
- 그래서 앱도 차의 주간/야간을 따름(`ui/Theme.kt`의 `DayPalette`/`NightPalette`, 안드로이드 야간 모드 = `isSystemInDarkTheme()`). 주간 색은 사용자 2차 시안에서 뽑음: 배경 #F2F3F7, 흰 카드와 옅은 그림자, 분홍 #F04D80, 값은 파랑 #256FD8, 글자 #151928, 선택 메뉴 #FBD9E4/#CA2F58. 야간은 1차의 어두운 톤
- 2차 시안 구성: 하트+도로 로고(`logo_mark`), 밝은 배너와 "내 드라이빙 프로필"(요일별 이동 막대, "주 5회 판교 삼평동 출근", 생활권·시간대는 파랑), 오늘의 추천 인연, "라이프 루트 매칭"(지도 + "이동 패턴이 매우 비슷해요" + 이유 체크 목록), 바로가기 카드 3개(드라이브 케미 → 오늘의 추천, 커넥트 토크 → 매칭/대화, 미트 포인트 → 만남 장소), 만남 장소 보기
- 시안의 "출장·서울↔대구" 예시 문구는 우리 데이터(판교 출퇴근)로 바꿈. "커넥트 토크"의 "이동 중에도 대화"는 주행 중 대화가 아니라 "운전 중엔 음성 알림, 정차하면 대화"로 고침

### Step 3. 매칭 서버와 추천 ✅
- 매칭(`core/Matcher`): 내 자주 다니는 길마다 상대의 가장 잘 맞는 길을 골라 점수. 목적지 동네(45%), 출발 시간대(45%: 겹치면 1, 30분 이내 0.6, 1시간 이내 0.3), 출발 동네(10%), 같은 요일 비율. 여기에 내 주요 동네 두 곳을 상대도 다니는지(20%). 50점 이상, 상위 5명
- 추천 이유 문장: "출근하는 동네(판교 삼평동)가 같아요", "평일 출근 시간대가 비슷해요 (07:50~08:20)", "같은 동네(분당 정자동)에서 출발해요", "출근 시간이 10분 차이예요" 등 강한 순으로 3개. 만남 동네는 두 사람의 출근 목적지
- 서버(`:server`, Ktor): `PUT /users/{id}`(프로필 + 생활 패턴, 운행 기록은 안 받음), `GET /users/{id}/recommendations`. 메모리에만 저장(차가 앱을 켤 때와 패턴이 바뀔 때 다시 보냄). 가상 사용자 4명(지연=B, 민서=C, 하은=D, 준호=E)은 시나리오 파일로 생활 패턴을 만듦
- 시나리오 결과(A 기준): 지연 76, 민서 70, 하은 64, 준호 36(추천 안 됨). `MatcherTest`, `ApplicationTest`
- (11/10) 추천은 한 번에 3명(`Users.SHOWN`). **다음에**(`PUT /users/{id}/passes/{other}`)를 누른 사람은 다시 추천되지 않고 그 사람의 관심도 안 보이며, 빈자리는 `REFILL_MS`(시연용 1분) 뒤 다음 사람으로 채워짐. 그 자리를 채울 가상 사용자 서윤(F, 59점)·유나(G, 53점)를 추가. 앱은 넘긴 사람을 자기에게도 기억하고(서버가 재시작해 잊어도 안 보이게) 10초마다 추천을 다시 받아 새 사람을 알림
- (11/10) 장소에 평점·리뷰 수, 메뉴(`MenuItem`: 시그니처, 리뷰 언급 수, 어울리는 관심사), 주차가 안 되는 곳의 공영주차장(`CarPark`: 이름, 걸어서 몇 분, 요금)을 붙임(모두 시연용 예시). 큰 지도에 P 표시, 길안내는 공영주차장으로. `MenuPicks.forTwo`가 두 사람의 관심사로 상대에게 권할 메뉴와 나에게 맞는 메뉴를 고름. 지도 타일은 연결이 없을 때 보관해 둔 상위 줌 타일을 잘라 확대해 채움(`OsmTiles.standIn`), 다운로드 실패 뒤 30초는 바로 대체
- 앱(`match/Matchmaker`): 차마다 무작위 id. 패턴이 생기거나 바뀌면 서버로 보내고 추천을 받음. 처음 추천된 사람은 소식으로("새 인연 추천이 3명 도착했어요"). 서버에 못 붙으면 30초마다 다시 시도. 프로필은 편집 화면이 생기기 전까지 시연용 "민준 31세"
- 앱 시작 직후 기어를 아직 모를 때 온 소식은 말하지 않고 모아 뒀다가, 상태를 알게 되면 한 문장으로 알림
- 배포: Render https://drive-mate-0ub6.onrender.com (사용자가 Blueprint 연결). 에뮬레이터 앱이 HTTPS로 패턴을 보내고 추천 3명을 받는 것까지 확인

### Step 4. 정차 중 매칭 흐름 ✅
- 서버: 관심(`PUT /users/{id}/likes/{other}`), 서로 관심이면 매칭. 매칭된 두 사람만 메시지(`POST /users/{id}/chats/{other}`, 200자). 차의 받은편지함(`GET /users/{id}/inbox`): 내가 관심 보낸 사람, 나에게 관심 보낸 사람, 매칭과 대화. 기록을 지우면 서버에서도 삭제(`DELETE /users/{id}`). 30분 넘게 소식이 없는 차는 추천하지 않음(가상 사용자는 항상)
- 가상 사용자(`server/.../DemoUsers`)가 사람처럼 움직여서 차 한 대로 전체 흐름을 시연: 새 차가 자기 기준 80점 이상이면 45초 뒤 먼저 관심(지연), 관심을 받으면 70점 이상일 때 20초 뒤 관심을 돌려줌(지연·민서, 하은은 안 함), 메시지에는 8초 뒤 답장
- 앱(`match/Matchmaker`): 10초마다 받은편지함을 확인. 나에게 온 관심, 매칭, 상대 메시지는 소식으로. 주행 중에는 "지연님이 회원님께 관심을 보냈어요. 정차한 뒤 화면에서 확인하세요"처럼 음성만(메시지 내용은 읽지 않음). 한 번 알린 것은 앱을 다시 켜도 다시 알리지 않음
- 추천 카드: "회원님께 관심을 보냈어요" / "관심 보냈어요" / "매칭 성사" + "대화하기". 매칭되면 사진 공개(사진이 없는 사람은 "아직 사진을 올리지 않았어요")
- 매칭/대화 탭: 왼쪽 매칭 목록(마지막 메시지), 오른쪽 대화. 보내는 말은 정해진 문장 3개 중에서 고름(자유 입력 없음). "만남 장소 정하기 →"는 Step 5로
- 소식 칩을 누르면 소식을 모두 읽음으로 하고, 매칭·메시지 소식이면 그 대화를 엶. 주행 후 정차하면 보던 탭과 대화로 돌아옴
- 확인(에뮬레이터 + Render): 앱 시작 → 주행 중 지연의 관심(음성) → 정차(카드에 표시) → 관심 있어요 → "지연님과 매칭됐어요" → 소식 칩으로 대화 열기 → 인사 → 주행 중 답장(음성) → 정차 후 같은 대화에서 답장 확인. 서버 테스트 7개

### Step 5. 만남 장소 추천 + 길안내 ✅
- 장소 추천(`core/MeetingPlaces`): 두 사람의 퇴근길(저녁 자주 다니는 길의 출발 → 도착)에서 각자 얼마나 더 돌아가는지 계산. 둘 다 5km 안쪽인 곳 중 합이 작고 한쪽만 손해 보지 않는 곳 3개. 퇴근 시간대가 겹치면 "두 분 모두 평일 18:40~19:00쯤 퇴근길에 올라요"
- 장소 목록(`server/.../PlaceCatalog`): 시연 지역의 가상 제휴 카페·식당 10곳(이름·혜택은 예시, 주소는 동 단위). 제휴 혜택 표시는 사업성(지역 상권 제휴) 시연용
- 흐름: 매칭된 사람에게 "제안하기" → 상대가 수락(가상 사용자는 8초 뒤) → 약속 확정. 상대가 제안하면 "수락하기". 제안·수락·확정은 소식으로("지연님과 드라이브 브루 정자에서 만나기로 했어요", 주행 중엔 음성만). 대화 화면 위에 약속 한 줄
- 길안내(`navi/Navigator`): 확정된 장소를 NaviHelper `requestRoute`로 차 내비게이션에 목적지로 보내고 `requestNavigationScreen(Foreground)`로 내비 화면을 앞으로. 권한 `NAVI_ROUTE`, `NAVI_ROUTE_SEARCH`, `NAVI_CUSTOM_MAP`
- 확인(에뮬레이터 + Render): 매칭 → 만남 장소 3곳 → 제안 → 지연 수락(음성) → 길안내 시작 → 차 내비가 앞으로 나오며 "드라이브 브루 정자, 19분 · 6.6km" 경로 안내 시작("안내를 시작합니다"). 기관망은 HTTPS를 가로채서 내비 앱이 자기 서버에 못 붙으므로, 휴대폰 USB 테더링 + `tools/tether_proxy.py`로 에뮬레이터 통신만 테더링으로 보내서 확인(CLAUDE.md 참고)

### Step 6. 신뢰·안전 ✅
- 모의 본인인증(`server/.../Verification`, `VerifyPage`): 정차 중 설정 화면에 QR → 휴대폰으로 인증 페이지(통신사 본인확인 흉내, 생년월일로 만 19세 이상 확인) → "인증하기" → 차 화면이 2초 안에 "본인 인증 완료"로 바뀌고 음성 안내. 차에서 글자를 입력하지 않음(Pleos 가이드: 키보드보다 휴대폰·프리셋). 서버가 서명한 토큰을 차가 보관해 서버가 다시 켜져도 인증 유지(`VERIFY_SECRET`, 없으면 개발용 값)
- 인증해야 관심 보내기·메시지·장소 제안 가능(서버가 거절). 인증 전 추천 카드 버튼은 "인증하고 관심 보내기" → 설정으로
- 신고·차단: 추천 카드와 대화 화면의 "신고·차단" → 정해진 사유 4개 중 선택(신고하면 차단까지) 또는 "신고 없이 차단만". 차단하면 서로의 관심·매칭·대화·약속이 지워지고 추천에서도 빠짐. 신고 내용은 서버에 보관(운영팀 확인용, `/admin/reports`는 서버 자신만)
- 계정 삭제(설정, 두 번 눌러 확인): 차의 이동 기록·동의·인증과 서버의 프로필·관심·대화·약속을 모두 지우고 새 id로 처음 상태
- 만남 장소 화면에 안전 안내("공개된 장소에서, 실시간 위치는 공유되지 않아요, 언제든 신고·차단")
- 위치 정밀도 제한(약 1km 격자, 동 이름만)은 Step 2·3에서 이미 반영
- 확인(에뮬레이터 + Render): 인증 전 버튼 → QR → 휴대폰 인증(이 PC에서 대신 요청) → 차 화면 자동 전환·음성 → 지연 신고 → 추천에서 즉시 사라짐(서버도 확인) → 계정 삭제 → 서버 404·기록 0건·처음 화면. 서버 테스트 12개
